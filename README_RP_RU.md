# Ролевые команды — COMMAND SYSTEM by dainsleifswife

Команды отправляются прямо в обычном сообщении JanitorAI. Chat Memory и установка
лорбука для них не нужны. Можно написать несколько команд, затем текст сцены.
Регистр названий и режимов не важен; регистр имён и описаний сохраняется.

```text
//pace slow //slowburn active //detail rich
"Вы так и не ответили на мой вопрос."
```

Настройки сохраняются для **основного API-ключа** и действуют в других чатах с тем
же ключом — как прежние настройки прокси. В production они хранятся в Redis;
при локальном запуске без Redis — до перезапуска процесса. Для другой ролевой
проверьте `//rp status` или очистите настройки через `//rp reset`.

Это инструкции для модели: они не загружают wiki, не редактируют прошлые сообщения
и не гарантируют безошибочного соблюдения каждой детали.

## Включение, отключение и срок действия

| Команда | Действие |
| --- | --- |
| `//rp on` | Включить базовые литературные правила и сохранённые режимы. |
| `//rp off` | Приостановить правила и режимы, сохранив их настройки. |
| `//rp this` | Включить RP только для текущего запроса. |
| `//rp status` | Показать состояние, сохранённые и разовые настройки, состав. Не вызывает модель. |
| `//rp reset` | Сбросить все ролевые настройки, авторские заметки и добавленный состав. История чата и другие команды прокси сохраняются. |
| `//help rp` | Полная встроенная справка. |
| `//aboutme` | Настройки прокси вместе с состоянием RP. |

Обычная команда режима включает RP и сохраняет настройку. Для одного запроса
добавьте `this` после режима: `//pace fast this`. У переключателей можно написать
`//slowburn this`, у героев — `//cochar this (Pantalone)`.

`active` и `on` равнозначны; `nonactive` и `off` отключают соответствующую
настройку. Особый случай: `//surprise off` сохраняет явную просьбу не вводить
неожиданные повороты; `//surprise nonactive` снимает эту просьбу.

Сообщение только с ролевыми настройками возвращает подтверждение без вызова
модели и без дополнительного хода сюжета. Исключения: разовые режимы `this`,
выбор сценария, сводка, интерлюдия и переход сцены запрашивают ответ модели.
Если после команд есть текст сцены,
настройки применятся к нему сразу. Команды исполняются слева направо.
Старые команды вроде `//think`, `//prefill`, `//dice_roll` работают как прежде.

## Подача и развитие событий

| Команда | Смысл |
| --- | --- |
| `//pace slow\|normal\|fast` | Темп событий. Медленный темп сохраняет содержательные действия. |
| `//initiative low\|normal\|high` | Инициативность персонажей модели; управление пользователем не передаётся. |
| `//detail light\|rich` | Плотность значимых сенсорных, пространственных и поведенческих деталей. |
| `//focus dialogue\|action\|emotion\|balanced` | Акцент ответа. |
| `//length short\|medium\|long` | Ориентир: 100–200, 250–450 или 600–900 слов при достаточном содержании. Это не изменение лимита токенов. |
| `//knowledge limited\|shared` | Раздельные знания персонажей или совместная осведомлённость об установленных фактах. Тайные мысли пользователя не раскрываются. |
| `//consequences soft\|realistic\|severe` | Тяжесть обоснованных последствий решений и ошибок. |
| `//subtext light\|rich` | Выражение чувств через речь, молчание и действия. |
| `//conflict restrained\|open\|mixed` | Форма мотивированного конфликта. |
| `//surprise off\|low\|high` | Частота и масштаб неожиданных событий. |
| `//prose clear\|lyrical\|classical` | Ясная, образная или размеренная литературная проза. |
| `//voice canon` | Акцент на индивидуальной речи по доступному описанию персонажа. |
| `//reveal slow\|normal\|fast` | Скорость раскрытия тайн независимо от темпа внешних событий. |
| `//motives hidden\|visible` | Насколько повествование раскрывает читателю намерения персонажей. |
| `//tension low\|medium\|high` | Напряжённость, ожидание и неопределённость. |
| `//ending pause\|hook` | Завершать ответ на паузе или содержательной реплике/действии для продолжения. |
| `//format scene\|letters\|documents\|chat\|call` | Обычная сцена, письма, документы, переписка или звонок. Для соцсетей: `//format social media`. |

Для снятия любой такой настройки используйте `off`, кроме описанного особого
случая `surprise`. Для него снятие настройки — `nonactive`.

## Эмоциональные режимы

Все эти переключатели принимают `active / nonactive / on / off / this`:

| Команда | Смысл |
| --- | --- |
| `//romance active` | Романтический акцент с учётом уже сложившихся отношений. |
| `//slowburn active` | Постепенное развитие доверия, близости и примирения. |
| `//hatred active` | Мотивированная враждебность и эмоциональный конфликт. |
| `//angst active` | Вина, горе, утрата и внутренние противоречия. |
| `//dark active` | Моральная неоднозначность и тревожная атмосфера. |
| `//violence active` | Вымышленная опасность, бой и физическая конфронтация. |
| `//obsession active` | Вымышленная фиксация, зависимость и собственничество с последствиями. |

Любовь настраивается отдельно:

```text
//love hidden
//love active
//love semi-active (care, protectiveness)
//love off
```

Для `semi-active` можно указать несколько выражений через запятую:
`flirt`, `touch`, `jealousy`, `care`, `gestures`, `noticing`, `words`, `teasing`,
`obsession`, `cruelty`, `hatred`, `vulgarity`, `kisses`, `sudden kisses`,
`gentleness`, `protectiveness`, `attention seeking`, `luxury`, `gifts`, `worship`,
`adoration`, `softness`, `calmness`, `priority`, `devotion`, `service`, `dependency`,
`reverence`, `domesticity`, `possession`, `praise`, `submission`,
`confession by implication`, `rituals`, `coldness`, `violence`, `angst`.

Адресность задаётся квадратными скобками:

```text
//love hidden [Pantalone]
//hatred active [Dottore]
//love semi-active (care, protectiveness) [Capitano]
```

Без имени эмоциональные команды относятся к исходному персонажу бота и его
отношениям с пользователем. Именованная команда действует на выбранного героя.
Для явного изменения отношений между двумя героями можно использовать
`//relationship override (Dottore distrusts Pantalone after the missing report.)`.

## NPC и постоянные главные герои

```text
//npc active
//npc active (doctor)
//npcs active (guards and palace staff)
//npc nonactive
//npcs nonactive
```

NPC — самостоятельные второстепенные участники. Можно не задавать описание:
модель получит инструкцию выбрать подходящего человека или группу из контекста.
Режимы одного NPC и группы заменяют друг друга; настройка сохраняется до отключения.

```text
//cochar active (Pantalone)
//cochars active (Capitano, Dr. Ratio)
```

Главные герои добавляются к основному составу и не заменяют исходного персонажа.
У каждого собственные голос, цели, знания, реакции и отношения. Повторный вызов
добавляет новых участников, не стирая уже добавленных; одинаковые имена
объединяются без учёта регистра. Равная значимость не требует одинакового числа
реплик в каждом ответе. Поддерживается до 16 добавленных главных героев.

Краткое описание оригинального героя можно включить в скобки:

```text
//cochar active (Mira — older sister; 29; practical, protective, dry humor)
```

Чтобы снять статус одного героя: `//cochar nonactive (Pantalone)`.
Чтобы снять все добавленные главные статусы: `//cochars nonactive`.
Это прекращает специальную инструкцию о составе, сохраняя события в истории.

`//cast focus (Dottore, Pantalone)` сосредотачивает эпизод на выбранных участниках;
остальные остаются основными героями. `//cast off` снимает фокус.

## Сцены, сводки, форматы и перспективы

| Команда | Действие |
| --- | --- |
| `//scene stay` | Удерживать текущую сцену без самовольного скачка времени или места. |
| `//scene next (the next morning at the palace)` | Один переход по указанию пользователя; снимает удержание текущей сцены. |
| `//scene off` | Снять удержание. |
| `//recap` / `//recap short` / `//recap full` | Один ответ со сводкой установленных событий, обещаний, отношений и незавершённых конфликтов. Не продолжает сюжет и не записывает ничего в Chat Memory. |
| `//interlude (Pantalone; a private meeting with Dottore)` | Один отдельный эпизод с персонажами модели. |
| `//chat active` | Вымышленная переписка. |
| `//call active` | Вымышленный звонок. |
| `//social media active` | Вымышленные посты, комментарии и сообщения. |
| `//dream active` | Сон или видение отдельно от фактов реального мира истории. |
| `//flashback active` | Сцена в прошлом с соблюдением хронологии. |
| `//inner monologue active` | Внутренние мысли вымышленного персонажа, а не рассуждения модели. |
| `//multiple pov active` | Различимые перспективы персонажей модели. |
| `//scenario select active` | Приостановить сюжет и предложить 3–5 разных путей для выбора. Отключение: `//scenario select nonactive`. |

Все форматы (scene, letters, documents, chat, call, social media) заменяют друг
друга. Перспективы и сон/флешбэк — отдельные переключатели. `recap`, `interlude`
и `scene next` выполняются только для текущего запроса, в том числе когда
сообщение содержит одну такую команду.

## Авторские указания и исправления

```text
//plot override (Move the story to a court investigation.)
//relationship override (They are estranged spouses.)
//character override (He is more restrained in this alternate universe.)
//memory override (The princess has not opened the letter.)
//retcon (The meeting happened yesterday, not last week.)
//boundaries (No love triangle; no deaths in the main cast.)
```

Указание можно поместить в скобки или в сопровождающий текст сообщения.
Это явная авторская правка вымышленных фактов. Она не меняет правила приложения
или провайдера. `memory` и `retcon` сохраняют несколько последовательных заметок;
остальные указания того же типа заменяются новым. Добавьте `[Name]` для адресности.

Чтобы убрать соответствующие заметки/указание, используйте `//memory off`,
`//retcon off`, `//plot off`, `//relationship off`, `//character off` или
`//boundaries off`, при необходимости с тем же `[Name]`.

Одна заметка ограничена 2000 символами; в сумме сохраняется до 96 настроек и
24000 символов состояния. При превышении лимита команда покажет ошибку, сохранив
предыдущие настройки. Старые сообщения JanitorAI не редактируются.

## Качество и темы

`//quality active`, `//humanize active`, `//prose active` и `//writer mode` включают
одну настройку качества: естественная речь, конкретные детали, индивидуальный
характер и разнообразный ритм. Отключение — `//quality off`.

Темы включаются через `//название theme`, выключаются через
`//название theme off`; разовый вариант — `//название theme this`.
Можно сочетать несколько тем. Поддерживаются:

- `slice of life`, `angst`, `dead dove`, `enemies to lovers`, `horror`, `romance`;
- `stalker`, `abuse`, `cold`, `hanahaki`, `flirt`, `falling in love`, `fluff`;
- `toxic love`, `from strangers to lovers`, `love at first sight`, `selfish love`;
- `wilted garden`, `egoistic love`, `forbidden love`, `tragedy`;
- `corrosive affection`, `sarcastic spouses`, `fake relationship`, `hurt comfort`;
- `betrayal`, `reconciliation`, `betrayal and reconciliation`, `mutual unrequited love`.

Тема `reconciliation` сохраняет пользовательский смысл ложного обвинения и
попытки доказать невиновность. Для восстановления доверия после реального
предательства используется `betrayal and reconciliation`.

По просьбе пользователя команды 18+ и тема smut в расширение не включены.
Режим затемнения сцены не добавляется.

## Общие принципы

Включение атмосферы или романтического акцента не отменяет характер и уже
сложившиеся отношения. Для намеренного изменения фактов служат авторские
указания. Отключение режима не стирает уже произошедшие события.

Правила активных режимов собираются в один компактный блок. Полный справочник
не отправляется модели на каждом запросе. Автоматические баннеры и объявления
не возвращаются; подтверждения команд и сообщения об ошибках сохраняются.

Основа системы и исходная терминология: **dainsleifswife**.
